## 路由与 Hook

实际新 Codex CLI 会话自然语言触发 skill，然后一次 `run_task` 完成 15 步，报告 `codex-natural-route.json`。最终 `codex-discovery.json` 核验用户级唯一 skill、隐式触发、MCP 依赖、七个工具和受信任 Hook，以及 0.2 的 targets 参数。当前旧会话需新开才能取得更新的参数 schema。

真实新会话已拦截 `Bash` 中可识别的直接 GUI 导入，以及 `mcp__node_repl__js` 的直接 GUI 导入。`diagnose_task` 正常通过，拒绝后没有循环重试。一次 runtime 授权、绑定确切 session/tool/arguments 的调用已真实放行；跨 session/更改参数的受控调用被拒绝。见 `codex-hook-final-shell.json`、`codex-hook-final-node.json`、`codex-hook-fallback.json`。

本次当前真实会话的 `mcp__cua_repl.js` 也已被 PreToolUse 拦截，`cua-hook.json` 记录未执行且无重试。Bash 仅匹配可识别的直接驱动导入，引用 CUA 名称的普通报告文本不会误拦。间接脚本、宿主管理/特殊调用路径、未识别调用和用户手工操作不受此窄 Hook 保证。没有全局拦截 shell/MCP。Hook 是路由检查，不是任意代码沙箱；局部接管仍依赖当前受信任代理把具体调用限制在用户授权内。

## 生产使用边界

当前适合事先可描述流程、明确控件、明确输入/输出的低风险工作。任意程序启动、未知应用长程规划、新文本、语义候选缺失、低置信需 Astra；敏感登录和真实额外权限需用户。`optional_if` 只提供确定性跳过分支，没有任意流程编程语言。候选超过上限时可按真实分组检索；缺少可靠分组、未批准标签、预算不足会升级，不丢掉尾部候选。

UIA 锁定精确 HWND/PID/程序/标题及其拥有的对话框。标题或目标身份变化会保守升级。旧隔离 Edge 驱动已移除；当前官方 Chrome 路由使用用户实际配置/登录所在的浏览器，真实验收仅使用合成页面。程序、域名、路径和动作检查真实生效，但任意第三方应用点击后的业务含义仍需经过审核的契约/适配器；本原型不承诺对未知应用的所有副作用提供沙箱级约束。

Choice 分布、官方 confidence 和实际正确率是不同指标。新一轮 828 个真实合成评估用例后，英文网页和中文 Windows 的低风险 2–6 个按钮候选采用 0.95/0.90/0.15，其他范围保留工程值 0.97/0.90/0.15。候选放宽在验收阶段出现 6 次错误选择，涉及的配置未部署；最终配置在新 144 例中执行并验证 65 次，0 次错误动作，仍有 31 个正例未能独立完成。未宣称生产校准或任意 GUI 接管；细节及全部失败见 CALIBRATION.md。最新两组 Astra 实测位于清单的 benchmark_latest，实际账单仍 unavailable；本次校准未重测两组速度与费用。

首次剪贴板探测出现恢复事故：原内容未能确认恢复。已修正 CloseClipboard 序号时机，加入修改前的 DPAPI 恢复副本；后续实际恢复及用户变更保护测试通过，但无法回溯恢复那次已丢失的内存快照。此项影响保留在验收记录，不以新测试 PASS 掩盖。

局部语义词表增强 `gui-kind-rules-1` 已实测：文件/文件夹与使用指南/关于应用的中日英按钮选择。132 例前后对照和限制见 [修复报告](reports/semantic-kind-repair-20260923/REPORT.md)。这不代表所有文件操作或任意帮助应用已支持。
