# 浏览器目标模式

适用于已授权的公开网页导航、搜索、简单点击、填写和勾选。使用原来的 chrome_gateway.mjs/run_task 入口，契约加 `mode:"goal"` 和 `observation_policy:"public_ui"`，省略 steps 和 jev_label_allowlist。这是显式的公开 UI 观察范围，不自动适用于邮箱、内部系统、健康或财务等私有页面。

## 最小契约

```json
{
  "version": 1,
  "mode": "goal",
  "observation_policy": "public_ui",
  "goal": "在公开资料站使用给定词搜索资料。",
  "language": "zh",
  "target": {"driver":"browser","connection":"official_chrome","url":"https://example.org/"},
  "scope": {"origins":["https://example.org"],"actions":["click","fill","key"]},
  "inputs": {
    "term":{"value":"已授权检索词","purpose":"资料检索词"},
    "enter":{"value":"Enter","purpose":"执行公开搜索"}
  },
  "goal_options":{"input_refs":["term"],"search_submit_ref":"enter","batch_size":16},
  "success":[{"kind":"url_query","parameter":"q","input_ref":"term"}],
  "budget":{"steps":12,"jev_calls":16,"seconds":300,"reobservations":4,"no_progress":3}
}
```

example.org 和 q 仅示意；实际来源、输入、完成条件应来自用户目标和当前可核实的页面。已有页的 tab_id 与 URL 必须来自新鲜标签身份，不为了恢复刷新用户页面。

## 执行与证据

- 运行时观察每一步当前页面，形成允许的动作候选。Jev 只能选择这些动作，不能生成代码、输入文本、目标网址或权限。填入内容仍由本地输入引用供给。
- 公开控件的短名称、分区标题、导航标签、公开链接路径，以及短标题／状态文字可进入判断。输入值、整页正文、URL 查询串、截图、Cookie 和文件内容不会自动发给 Jev；可疑指令、密钥、联系方式会在本地过滤。private 页面继续使用 allowlist，不能将敏感页面简单标成 public_ui。
- 候选超出单批容量时，优先展示覆盖所有候选的分组，再选择组内动作；更大的证据才分批，低置信的否定不能直接丢弃该批。超过资源限制返回具体原因，不静默截尾。
- 点击重名控件时使用观察到的结构路径，并在执行前重新核对框架、可见性、角色、名称、上下文和当前值。没有区分证据的真正重名项仍暂停。
- 所有最终 success 条件必须由当前页面或本地文件验证，模型不能自行宣告完成。`changed` 仅用于运行时一步进展，不能作为目标完成条件。success 可用现有谓词、新增 url_path 或 url_query；查询值精确比较，支持 SPA 的一层额外编码。
- 将任务对象与结果字段区分开：点击目标应保留用户要求的主题、对象与限定，标题、作者、日期等通常是打开后读取的字段，不是点击前必须已知的值。验收使用能证明详情已打开的语义控件或稳定路径；卡片链接中的来源、统计、签名和临时查询参数不是业务完成条件，不要求它们跳转后保持相同或为空。
- 用户允许任意一条相关结果、而详情结构尚未观察时，不猜测“发送”“评论”等控件。可依据已观察的详情链接共同路径使用 `{"kind":"url_path_prefix","equals":"/items/"}`：要求进入该路径下非空子路径，根路径本身不会通过。它用于验收页面类型，不能代替 Jev 对内容相关性的判断；完成后用 page 正文核对实际信息。特定对象继续用精确 `url_path`。
- 已观察到且唯一匹配目标 URL 条件的链接由控制器执行，不强行调用 Jev。显式声明 search_submit_ref、仅一个检索输入且只有一个已识别公开搜索框时，填写也由控制器确定执行；多个搜索框仍交给 Jev 选择。同一搜索框完成给定输入的填写验证后才确定续接 Enter。普通表单提交、发布、支付等仍走原授权机制；目标模式不扩张权限。

## 恢复

CHROME_SEGMENT_COMPLETE 沿原 resume_task 接续。已经得到的模型判断只在同一观察指纹和请求下复用；输入改变、用户接管后清除。动作前重新核对当前页面、所选控件及表单状态；无关推荐内容变化不再使已选目标失效。目标或表单变化时重新观察与规划；已派发但结果不明时只能核对，不能重放。

首次导航返回异常时，若只读核对确认当前 URL 已是目标且没有弹窗，可以继续观察，无需再次导航；用户接管、急停及尚未到达目标的情况仍保留原停止行为。

LOW_CONFIDENCE 等需要补充时，优先使用 escalation_context；超过 24 项的完整候选保存在本地加密 decision-request.dpapi 中，摘要不偏选前几项。可以依据完整证据补一个 decision_override 后继续；一个控件对应多个动作时不能只凭控件 ID 猜动作。补充不会改变原契约、输入范围或授权。

若网页实际已到达目标但 URL 验收过时，先只读核对当前页面、查询词或结果内容，再修正验收或建立只读核对任务；不要重复提交。站点改版、登录／验证码、纯画布、封闭 Shadow DOM、非语义自定义控件、跨域未授权框架仍可能需要专项适配或局部接手。

## 当前范围

目标模式支持官方 Chrome 页面中的 click、fill、key（已授权公开搜索）、check、uncheck。公开搜索或新窗口链接打开的新标签可以自动跟随；独立多窗口操作继续使用步骤模式；不是所有 GUI 都已能独立探索。

自动读取可见 DOM 和开放 Shadow DOM；隐藏元素不占候选上限。最多扫描 30000 个 DOM 节点、保留 2400 个可见控件，并检查传输大小。超限是明确的能力边界，需缩小到相关页面或分段；不能声称已读取完整页面。public_ui 中未授权的外部 iframe 标记为不透明并保留主页面操作，使用量中报告数量。

交付区分 actions、jev_requests/http_attempts、goal_decisions、确定性决策和 astra_decision_overrides。零模型调用必须如实报告。真实测试和模拟测试分别计数；通过少量站点不能宣称全网可靠性或生产校准。


## 上游实现替换与结果读取（0.6.2）

采用 Browser Use jev-ultrafast 的 page-key/target-guard 思路，以及 jkudish/jev-browser 的 settle/extractPayload 流程；具体来源、固定提交和 MIT 许可保存在运行时 vendor/ 下。适配仍使用官方 Chrome 会话，未改用第三方 CDP 浏览器、候选截尾或宽松模型阈值。这两个项目分别为 MVP 和早期软件，不能声称全网成熟稳定。

公开页面首次导航后等待有限的 DOM 稳定；允许范围内的实际跳转地址用于绑定。动作后在最多 10 秒内核对结果，期间不重新点击或提交。目标模式已访问过的同一导航链接不会因推荐变化再次执行；GOAL_DESTINATION_ALREADY_VISITED 表示应只读核对实际目标及验收条件，不能盲目重放。

completed 的 public_ui 任务在清理临时标签前回传 page，字段为 tab_id、url、title、format:text、content、true_length、truncated。直接使用这份实际页面结果回答信息任务；无需重新打开页面再导出。正文最多 16000 字符，超出时明确 truncated；正文只回传本地调用者，不发送给 Jev。读取失败会出现 page_read_error，不能把动作完成当成已经读到内容。非 public_ui 契约继续使用显式 read/export。

公开搜索 Enter 和 target=_blank 的链接点击，采用上游动作后跟随新页的流程。只认领动作后新出现、在授权来源范围内且匹配观察链接路径或声明 URL 验收的新标签；多候选不猜。已有标签不进入匹配，不能证明归属的新页保留，绝不自动关闭。适配不修改网页 target 属性，不重复提交；仍须在实际页面验证目标。

搜索是长流程的中间步骤时，还会用已填写并核验的搜索词匹配新标签的查询值，不要求中间搜索页满足最终详情页的验收条件；重复查询参数与不匹配词仍拒绝。

返回 page.tab_id 和 page.url 是当前实际结果标签的身份。后续契约据此续接；任务最初的 target.tab_id 可能仍是首页，不能将它当作新结果页。源页跟踪参数变化不等于已进入结果；先匹配动作打开的新标签，再验证当前页导航。

输出路径已存在（CHROME_OUTPUT_EXISTS）会结束任务并释放锁，原文件保持不变。需要新的输出路径时创建新契约；若其他错误仍处于 paused/escalated，决定改用新契约前先取消旧任务。不要把自己的旧任务占锁误判为其他代理正在操作。导出临时文件使用每任务唯一名称；公开页面已有 page 时优先直接使用回传内容。


## 独立候选判断（0.7.0）

目标保持用户要求的范围；用户只要求一篇相关内容时，将相关性条件交给目标模式，不由主模型提前挑选标题或作者。结果返回后再解读正文。

排名低置信时，运行时依据 TypeSafe 的独立候选判断和多问题并行模式，对完整候选逐项验证是否构成合适的下一步。多个结果可以分别合格，不要求它们争夺唯一答案；各项仍满足原有 probability、confidence 和 margin 门槛。多个合格结果再按官方 Noul 重排模式比较与具体目标的相关性，避免列表顺序或泛泛相关项的较高置信度压过直接匹配项。重排仅在已合格集合内排序，不提升不合格候选、不代替原门槛。弱否定不丢弃候选，未知或预算不足明确停止。

模型响应格式异常时，同一只读判断最多自动恢复一次，并纳入原调用预算；低置信不以相同证据反复请求。此恢复不会重放网页点击或发布动作。

若独立判断仍只有不确定候选，按同一重排模式比较完整候选后，仅将最佳项及未改变的用户目标交给一次聚焦 Choice 核对。这一步移除其他候选干扰，仍需通过原有三个门槛；Noul 分数本身不能放行动作。全体明确否定、聚焦核对不通过或预算不足均停止。

公开链接额外读取有界的邻近卡片文字，以保留作者等区分信息。表单输入不进入该上下文，可疑指令、联系方式及凭据继续过滤；动作前重新核对这份邻近信息。公开正文读取包含可见 time／自定义时间控件的 datetime 及邻近文字，避免仅依赖 innerText 漏掉发布日期。

参考：https://docs.typesafe.ai/cookbooks/rerank_typesafe 、https://docs.typesafe.ai/primitives/choice 。此结构修复不等于生产校准，也不保证所有网页或任务均可独立执行。
